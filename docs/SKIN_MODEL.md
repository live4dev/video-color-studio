# Воспроизведение локальной модели кожи

## Алгоритм v2: локальное согласие и частичные маски

В рабочей ветке версия алгоритма `semantic-consensus-components-v2` использует
те же проверенные SelfieMulticlass-веса. Шесть карт классов сохраняются для всех
четырёх ориентаций полного кадра и областей человека. Кожа требует минимум двух
сильных геометрических подтверждений и отсутствия сильного отрицательного
предсказания в той же области; противоречие означает отказ. Увеличенная
область не заменяет автоматически все классы под ней.

Пригодность оценивается отдельно по компонентам. Состояние `needs-review` может
содержать надёжные обрабатываемые участки, если диагностика явно сообщает
`automatic_accepted=true` и положительное число `accepted_components`. Отсутствие
такого подтверждения по-прежнему отключает автоматическую кожу. UI и трекер
различают неполноту маски и полную недоступность; ручные штрихи применяются последними.

Raw cache ограничен 64 МиБ и хранится только в памяти; ключ зависит от входного
RGB, подсказки человека, версии алгоритма и SHA модели. Диагностика содержит
`skin_algorithm_version`, `skin_models` и происхождение геометрических прогонов;
растровые карты не передаются через MCP и не меняют схему проекта 1.

Изменение обвязки и успешные технические тесты не подтверждают подводную точность.
Замена установленной сборки разрешается лишь после прохождения неизменных
положительных и отрицательных проверок. Альтернативные модели остаются отдельными
developer-кандидатами до численной проверки, проверки происхождения и приёмки.

## Веса и преобразование

Приложение поставляется с Google MediaPipe SelfieMulticlass 256×256 float32 v1,
преобразованной из официального TFLite в ONNX. Конвертация не меняет обученные веса.
Нормализация — RGB float32 `[-1,1]`, вход NHWC `[1,256,256,3]`; выход — шесть каналов
logits `[1,256,256,6]`. Для вероятностей применяется softmax по последней оси.
Классы по индексам: фон, волосы, кожа тела, кожа лица, одежда, аксессуары.

Официальные встроенные `NormalizationOptions` задают mean=127,5 и std=127,5 для
8-битного RGB. Для внутреннего RGB `[0,1]` это `2 * rgb - 1`. Эти значения инструмент
читает непосредственно из проверенных TFLite-байтов; сторонние описания `[0,1]`
для этой модели неверны.

Точные SHA исходного и полученного файлов, имена тензоров, версии инструментов,
численная проверка и официальный источник находятся рядом с весами в
`src/freedive_color/assets/models/SELFIE_MULTICLASS_METADATA.json`.
Apache-2.0 и attribution поставляются в `SELFIE_MULTICLASS_LICENSE.txt` и метаданных.

## Конвертация разработчиком

Нужна изолированная среда Python 3.11. Системная или рабочая среда приложения
не изменяется; TensorFlow и tf2onnx не нужны конечному пользователю.

```sh
uv run --no-project --python 3.11 \
  --with tensorflow==2.15.1 --with tf2onnx==1.16.1 \
  --with numpy==1.26.4 --with onnx==1.17.0 \
  --with onnxruntime==1.23.2 --with protobuf==3.20.3 \
  python tools/convert_skin_model.py \
  --source build/skin-model/selfie_multiclass_256x256.tflite \
  --download \
  --output build/skin-model/selfie_multiclass_256x256.onnx \
  --report build/skin-model/conversion.json
```

`--download` разрешает единственную явную developer-загрузку по versioned HTTPS URL.
Без флага используется только локальный исходник. Несовпадение исходного SHA
завершает процесс до конвертации; существующий файл не заменяется другой моделью.
Экспортёр запускается с фиксированным `PYTHONHASHSEED=0`, opset 17 и закреплёнными
версиями. Полученный SHA должен совпадать с константой в инструменте.
Внутренние имена и порядок независимых узлов tf2onnx канонизируются по содержимому
графа; внешний интерфейс и численные значения весов сохраняются. Совпадающие
константы и чистые операции разделяют одно представление. Проверка TFLite выполняется
после канонизации.

После конвертации пять синтетических тензоров во всём рабочем диапазоне `[-1,1]`
обрабатываются TensorFlow Lite CPU и ONNX Runtime CPU. Максимальная разница logits
должна быть ≤0,002, согласие
классов — ≥99,9%. Эта проверка подтверждает эквивалентность преобразования, а не
правильность выделения кожи на реальных людях или под водой.

Проверенная сборка: [GitHub Actions 41193200816](https://github.com/live4dev/video-color-studio/actions/runs/41193200816),
Ubuntu 22.04, два независимых экспорта с побайтным сравнением. Размер — 16 381 788
байт; SHA-256 `cd2dff0e466a1ce493f2f9d8a9452e2dfbe500695ae4cf77f8d3a57c089c6856`.
На пяти тензорах максимальная разница logits составила 0,000073243, согласие классов
100%. Скачанные артефакты также сравнены локально и проверены по SHA.

## Проверка перед упаковкой

```sh
python tools/verify_models.py
```

Оба сборщика выполняют эту проверку до упаковки. Проверяются сами веса по SHA,
соответствие provenance и наличие лицензии. ONNX Runtime и его динамические
библиотеки входят в standalone; notices собираются из фактического wheel.
Приложение использует только CPU provider, отключает телеметрию перед созданием
session и не загружает недостающую модель из сети. Если локальная модель отсутствует,
изменена или inference недоступен, автоматическая кожа отключается с предупреждением.

ONNX Runtime 1.23.2 имеет wheel для Python 3.12/3.13 и Windows x64/macOS arm64/x86_64.
У проверенного stock wheel macOS arm64 метка 13.0, но оба фактических Mach-O требуют
13.4. Поэтому для поставки с целевым macOS 13.0 нужен отдельный CPU build из тех же
исходников 1.23.2 с `CMAKE_OSX_DEPLOYMENT_TARGET=13.0`; stock wheel строгую проверку
поставки не проходит. Заголовки бинарников не переписываются. Наличие wheel,
корректные заголовки или успешная упаковка не заменяют нативный smoke-test на каждой
целевой системе.

Подготовка CPU runtime перед локальной macOS-упаковкой:

```sh
uv pip install --python .venv/bin/python --no-deps \
  cmake==3.31.6 ninja==1.11.1.3 wheel==0.45.1
uv run --no-sync python tools/build_onnxruntime_macos.py --jobs 2 --install
```

Сборщик проверяет закреплённый commit 1.23.2, зависимости из upstream `deps.txt`,
все Mach-O slices и настоящий CPU inference в отдельном процессе. Перед freeze
`build_desktop.py` сверяет установленные native-библиотеки по SHA с этим отчётом;
замена на stock wheel после проверки останавливает упаковку. В поставку попадают
`native-onnxruntime/` с notices и отдельный `onnxruntime-native-manifest.json`,
сохраняющий также прежний OpenCV manifest. CI выполняет исходную сборку runtime
перед тестами и упаковкой. После установки собственной сборки используйте
`uv run --no-sync`, чтобы обычный sync не вернул wheel из PyPI.
