# Техническое задание для Codex: Freedive Color Studio

**Тип продукта:** локальное desktop-приложение для Windows и macOS.  
**Задача:** автоматическая и ручная цветокоррекция подводных фотографий и видео, в первую очередь с людьми во время фридайвинга.  
**Приоритет:** достоверность исходной сцены и внешности человека выше выразительности эффектов.  
**Язык интерфейса v1:** русский, структура для добавления английского.  
**Модель работы:** offline-first, без регистрации, облачного API и отправки материалов на сервер.

## 0. Главная инструкция исполнителю

Ты — ведущий инженер по desktop-приложениям и компьютерному зрению. **Создай работающий продукт, а не только архитектурное описание или прототип экрана.** Разрабатывай итерациями с тестами и запускаемыми артефактами. В первую очередь доведи обработку фотографий до рабочего состояния, затем реализуй видео на том же движке. Не имитируй готовность функции. Если на текущей ОС невозможно проверить другую платформу, подготовь CI-сборку и явно укажи, что было реально проверено.

При обнаружении неоднозначностей принимай прагматичные решения, документируй их в `DECISIONS.md` и продолжай реализацию. Не пытайся применить исходный художественный промпт к генеративной модели как единственный алгоритм: переведи его в измеримые настройки, маски, ограничения и визуальные критерии качества.

## 1. Целевой сценарий

1. Пользователь перетаскивает в приложение фотографии, видеоролики или папку.
2. Приложение извлекает метаданные, создаёт миниатюры и предварительно анализирует сцены.
3. Пользователь выбирает пресет **Natural** (по умолчанию), **Cinematic** или **Vivid**.
4. Автоматический алгоритм исправляет цвет воды, контраст и оттенок кожи. По возможности различает человека/кожу, воду, дно и участки над водой.
5. В просмотрщике доступны «до/после», сплит-слайдер, увеличение 100%, отображение масок, ручные регуляторы.
6. Можно выбрать хороший кадр как **визуальный референс** и применять его палитру к серии, но не копировать экспозицию и цвет механически.
7. Кнопка «Обработать всё» сохраняет отдельный результат для каждого исходного файла. Оригиналы не меняются.
8. Для видео сначала генерируется короткое превью, затем экспортируется целый ролик с исходной частотой кадров и синхронным звуком.

## 2. Поддерживаемые платформы и поставка

- **Windows:** Windows 10/11, x64. Должен быть установщик и/или standalone portable-папка с `.exe`.
- **macOS:** macOS 13+, Apple Silicon (arm64) как основной приоритет; Intel (x86_64) — отдельная сборка при возможности. Формат `.app`, поставка через `.dmg` или `.zip`.
- Для конечного пользователя **не нужны Python, pip, FFmpeg в PATH, терминал или ручная установка зависимостей**.
- Без GPU программа должна работать на CPU с пониженной скоростью. GPU-ускорение — опционально.
- Пользователь может указать каталог для временных файлов; приложение оценивает доступное дисковое пространство до экспорта.
- Реализовать сборочные скрипты на каждой ОС и CI-матрицу Windows/macOS. Подпись Windows и notarization macOS — отдельный финальный шаг, если есть сертификаты; не утверждать, что приложение подписано без действительной подписи.

## 3. Технологический стек

**Обязательный:**
- Python 3.12+ (зафиксировать проверенную версию), Qt/PySide6 для desktop UI.
- NumPy, OpenCV для обработки и анализа изображений. При необходимости Pillow + ImageCms для ICC.
- FFmpeg/ffprobe как изолированный media backend для декодирования/кодирования видео и работы с аудио.
- PySide6 deployment через `pyside6-deploy`/Nuitka либо технически обоснованную альтернативу.
- `pytest` для автотестов, `ruff` для lint/format, GitHub Actions для сборок.

**Опционально, после базового MVP:**
- ONNX Runtime + лицензируемая для распространения модель сегментации человека/кожи. Проверять доступность execution provider во время выполнения; CPU обязателен, CoreML на Apple и подходящий ускоритель Windows при наличии совместимой сборки.
- Никакого обязательного облачного inference. Не использовать diffusion/inpainting/генеративную замену частей кадра.

**Зависимости и лицензии:** выбрать FFmpeg-сборку и кодеки с учётом LGPL/GPL и правил распространения; хранить в репозитории `THIRD_PARTY_LICENSES.md` и документировать происхождение бинарников/моделей. Не считать, что произвольную GPL-сборку FFmpeg можно без проверки включить в закрытый дистрибутив.

## 4. Функции обработки изображений

### 4.1. Сохранение геометрии
- Запрещены изменение пропорций тела и лица, дорисовка конечностей/пальцев, замена волос, купальника, маски, ласт, украшений и фона.
- Сохранять исходные ширину/высоту, положение объектов, перспективу, кадрирование и свободное пространство. Никакой автоматической обрезки.
- Допустимы только поканальная и локальная цветокоррекция, контролируемое шумоподавление, мягкая резкость, негеометрические маски. Отключить любые «beautify» и face restoration, изменяющие идентичность.
- Бережно сохранять пузырьки, взвесь, отражения, волны, пряди волос и границу вода/воздух.

### 4.2. Глобальная и пространственная цветокоррекция
- Компенсировать избыточный зелёный/циановый оттенок и снижение красного, но **ограничивать усиление отсутствующего/зашумленного красного сигнала**.
- Сохранять естественную бирюзово-синюю палитру: у поверхности светлее, в удалении и тени темнее/холоднее. Избегать неонового циана и одинакового оттенка на всём изображении.
- Не использовать безусловный алгоритм gray-world на целой подводной сцене: вода закономерно имеет доминирующий цвет.
- Контролируемо корректировать экспозицию, локальный контраст и прозрачность воды, без агрессивного dehaze/HDR-ореолов.
- Свет и каустика: **подчёркивать только реально существующие** лучи/узоры. Нельзя синтезировать новые солнца, светящиеся сферы или повторяющиеся сетки.
- Детализация дна, песка, скал и кораллов должна усиливаться умеренно; дальние участки остаются мягче.

### 4.3. Кожа и человек
- Создать **отдельную маску видимой кожи**, не путать её с маской всего силуэта человека. Купальник, ласты, маска и волосы должны исключаться из skin correction.
- По возможности использовать семантическую сегментацию; дополнять её цветовым анализом внутри области человека и проверками уверенности. При низкой уверенности снизить силу коррекции или отключить её и показать предупреждение.
- Корректировать локально зеленоватые, циановые, серые и пурпурные сдвиги до естественной умеренно тёплой кожи. Оставлять холодные рефлексы воды и объём теней. Не выравнивать тело до одного цвета.
- Сохранить поры, складки и фактуру. Не применять сглаживание формы тела и генеративную реконструкцию лиц.
- Маски растушёвывать с учётом границ объекта; не допускать контурных ореолов вокруг волос, кожи, маски и ласт.
- Предусмотреть ручные коррекции маски кистью «добавить/вычесть», а также глобальную настройку силы воздействия.

### 4.4. Кадры над и под водой
- Для split-level кадров обнаруживать или вручную задавать границу вода/воздух.
- Корректировать надводную и подводную часть раздельно; сохранять исходную линию волны и преломление.
- Избегать видимого шва между масками, изменения цвета неба и искусственного выпрямления поверхности.

### 4.5. Работа с цветовым пространством
- Корректно применять EXIF Orientation и ICC для фотографий, не менять геометрию и не терять цветовой профиль незаметно.
- Разделять декодирование, линеаризацию (когда применимо), коррекцию и преобразование при экспорте. Внутренние операции выполнять с float32 или более подходящей точностью; избегать многократного 8-битного округления.
- MVP: стандартные SDR фото/video. HDR/PQ/HLG/Log распознавать; либо выполнять явно выбранный и протестированный SDR tone mapping, либо информировать о неподдерживаемом режиме. **Не применять SDR-фильтры молча к HDR.**

## 5. Фото

- Вход MVP: JPEG/JPG, PNG, TIFF (8/16 бит — в пределах возможностей декодера); HEIC/HEIF и RAW — опционально, с явной индикацией поддержки.
- Выход: JPEG (настройка качества), PNG и TIFF; без коллажей, watermark и добавленных надписей.
- Одно входное изображение -> одно выходное изображение, с неизменным соотношением сторон и размерами, если пользователь не указал отдельный экспортный resize (по умолчанию OFF).
- Пакетная обработка папки; индивидуальные поправки и исключения внутри серии; пресет серии и per-image overrides.
- Сохранять историю настроек в sidecar JSON/проекте и метаданные, насколько это совместимо с форматом и приватностью; геоданные можно сохранять по выбору пользователя.

## 6. Видео

- Вход: MP4/MOV; MVP-кодеки H.264 и HEVC, если присутствуют совместимые декодеры; поддержка VFR/VBR через корректные временные метки.
- **Нельзя обрабатывать каждый кадр независимо одними и теми же эвристиками** — появится мерцание. Делать shot detection, анализ репрезентативных кадров, вычислять параметры для фрагментов и интерполировать их во времени.
- Маски человека/кожи стабилизировать во времени; предусмотреть трекинг/интерполяцию масок и анализ ошибочных границ. Исключить pumping яркости, hue flicker и мерцающие ореолы.
- Строить быстрый proxy для предпросмотра; применять те же вычислительные параметры к полному разрешению при финальном экспорте.
- Экспорт: MP4/H.264 SDR Rec.709 по умолчанию; дополнительно HEVC/10-bit только после проверки доступных кодеков, цветового управления и лицензий.
- Сохранять исходную частоту кадров либо временные метки (включая VFR), порядок кадров, разрешение, пропорции, оригинальный звук и A/V-синхронизацию. Не обещать буквального сохранения всех метаданных без проверки.
- Предварительная обработка 10–15 секунд с выбором диапазона. Возможность остановить и отменить экспорт без порчи оригиналов.
- Для длинных роликов — потоковая/чанковая обработка; не загружать все кадры в RAM.

## 7. Профили и управление

**Natural (default):** максимальная достоверность кожи и воды, умеренный контраст, слабый dehaze, минимальные эффекты.  
**Cinematic:** несколько более выраженная тональная сепарация, мягкие света, аккуратный контраст, без искусственной подсветки или изменения сцены.  
**Vivid:** более насыщенная вода/локальные цвета, но с лимитами на неоновые оттенки и кожу.

Для каждого файла доступны: Exposure, Temperature/Tint, Red Recovery, Water Hue/Saturation, Skin Warmth/Strength, Contrast, Dehaze, Denoise, Detail, Highlights/Shadows, Mask Refine. Регуляторы работают локально/глобально согласно назначению, с понятными диапазонами и кнопкой сброса. Пользователь может сохранить собственный пресет и применить его ко всей серии.

**Reference Match:** выбор эталонного файла/кадра, подбор близкой палитры кожи и воды через устойчивые статистики и маски; без переноса лица, одежды, структуры или механического выравнивания освещения.

## 8. Интерфейс

Приложение с 3 областями:
1. **Слева:** библиотека/миниатюры, тип файла, статус анализа и экспорта, выделение группы.
2. **По центру:** большой viewer, переключатель Before/After и вертикальный сплит-слайдер; zoom/pan, 1:1, fit, отображение масок. Для видео — timeline, play/pause, выбор участка предпросмотра.
3. **Справа:** пресеты, группы настроек Water / Skin / Light / Detail / Export, выбор референса.

Снизу — очередь заданий, прогресс, возможность отмены, текст причин ошибок. Drag & drop и стандартные диалоги открытия обязательны. На больших файлах UI не должен зависать: фоновые worker-процессы/потоки с ограниченным потреблением памяти.

## 9. Архитектура и структура репозитория

Разделить UI и вычислительный движок, чтобы те же алгоритмы можно было запускать из CLI и тестов.

```text
freedive-color-studio/
  AGENTS.md
  README.md
  DECISIONS.md
  THIRD_PARTY_LICENSES.md
  pyproject.toml
  src/freedive_color/
    __main__.py
    ui/                   # PySide6, viewer, очередь, маски
    core/
      media_io.py         # загрузка, ICC/EXIF, метаданные
      color_pipeline.py   # градация, gamut/тон, точность
      analyze.py          # анализ сцены/кадров
      masks.py            # person/skin/water/over-under
      image_pipeline.py   # фото
      video_pipeline.py   # video/temporal smoothing
      presets.py
      project.py          # JSON проекта и sidecar
    integrations/
      ffmpeg.py
      inference.py        # опциональный ONNX backend
    cli.py
  assets/presets/
  tests/unit/
  tests/integration/
  tests/visual/
  tools/                  # воспроизводимые тестовые данные
  packaging/windows/
  packaging/macos/
  .github/workflows/
```

Выполнить CLI, использующий ровно тот же `core`, что и UI:

```bash
python -m freedive_color --input ./input --output ./output --preset natural
python -m freedive_color --input ./input/dive.mp4 --output ./output/dive.mp4 --preset cinematic --preview-seconds 15
```

Формат проекта: JSON с версиями схемы, исходными путями, выбранным пресетом, настройками файла, референсом, информацией о декодере и результатами анализа. Любая обработка должна быть воспроизводима с сохранёнными параметрами.

## 10. Жёсткие ограничения качества

Не изменять лицо, фигуру, позу, пальцы, длину конечностей, ракурс, форму одежды, ласты, маску, волосы, подводный рельеф, рыб и фон. Не создавать новые объекты, каустику, лучи, пузыри, боке или источники света. Не создавать одинаковый цвет воды по всему кадру. Не делать оранжевую кожу, зелёную кожу, пластиковые лица, «хрустящий HDR», ореолы по контуру или чрезмерный dehaze. Не выводить текст/логотип/водяные знаки на результат. При недостаточной информации в красном канале **не заявлять о восстановлении точного исходного цвета**: использовать умеренную оценку с возможностью ручной корректировки.

## 11. Приёмочные критерии

1. UI работает без установленного Python на реальной Windows x64 и macOS arm64 машине (Intel Mac — отдельно при выпуске соответствующей сборки).
2. Содержимое папки с 20 фотографиями обрабатывается по одной: ровно 20 отдельных выходных файлов, ни один исходный файл не изменяется, имена и результаты детерминированы.
3. Размеры, соотношение сторон, исходное расположение человека и предметов не меняются; нет автоматического кропа и генеративных объектов.
4. Скин-маска не включает яркий купальник, маску и ласты на тестовых примерах; при сомнительной маске программа явно ослабляет коррекцию.
5. Для mixed above/below-water кадров доступно независимое редактирование воды и неба, без изменения линии поверхности.
6. Есть три различимых, но естественных пресета, сохранение пользовательских настроек и их применение к группе.
7. Сплит-viewer и просмотр масок действительно показывают результат движка, а не декоративное демо.
8. Для MP4/MOV есть превью и финальный экспорт с проверкой длительности, FPS/PTS, разрешения, аудио и отсутствия заметного фликера на устойчивой сцене.
9. Файлы не загружаются в сеть. Работа без интернета подтверждена. Приложение не требует API-ключа.
10. Есть unit/integration/smoke тесты, GitHub Actions для Windows/macOS, команды локальной сборки и проверки, инструкции `README.md`.
11. Ошибки (битое фото, неподдерживаемый формат, нехватка места, отсутствие кодека, некорректный профиль цвета) обрабатываются с понятным сообщением и без перезаписи оригинала.
12. Проверены или явно маркированы как непроверенные сборки Windows/macOS. Не заменять факт тестирования обещанием совместимости.

Подготовить тестовый набор с согласованными правами: однотонная вода, человек с купальником, сильно зелёный кадр, темнокожая/светлокожая модель, чёрная маска, видимое дно, split-level, кадр с лучами, короткий статичный видеоклип и видеоклип со сменой глубины. Для каждого нужен визуальный регресс-тест или контролируемое сравнение кадров «до/после» и автоматическая проверка инвариантов. Не включать в публичный репозиторий личные фото без разрешения.

## 12. План реализации и контрольные точки

### Этап A — фото-MVP
- Создать репозиторий, архитектуру, стартовый PySide6 UI, import/export JPEG/PNG/TIFF, pipeline на float, три базовых пресета, drag & drop и before/after.
- **Готово, когда:** пользователь может реально импортировать фото, увидеть результат, изменить настройки, экспортировать отдельный файл. Не переходить дальше без рабочего демо.

### Этап B — локальная обработка и серии
- Добавить маски кожи/человека/воды, локальную цветокоррекцию, split-level, ручную маску, reference match, batch export, тестирование на референсных сценах.
- **Готово, когда:** массовая обработка серии не портит купальник/лицо и сохраняет индивидуальное освещение каждого снимка.

### Этап C — видео
- Добавить FFmpeg decoder/encoder, scene segmentation, temporal smoothing, preview, timeline, потоковую обработку, аудио и сохранение временных меток.
